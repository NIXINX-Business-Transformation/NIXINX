# Portal comercial mínimo — prueba de contratación
## Alcance autorizado
Login y registro de cliente, perfil (nombre, empresa, correo, acrónimo permanente), selección de Corporate existente y pago único de prueba mediante Stripe Checkout. El portal produce una solicitud de aprovisionamiento de prueba; no modifica Control, aplicaciones, gobernanza, P03, Engine, plantillas o Blueprint. No implementar suscripciones, pricing comercial, estados de cuenta, soporte ni gestión de usuarios de aplicaciones.
## Configuración pendiente

Habilitar Email/Password y verificación de correo, revisar IAM y reglas deny-all para las colecciones comerciales server-side. `CUSTOMER_FIREBASE_WEB_API_KEY` es la API key del mismo proyecto. Usar las credenciales Firebase server-side existentes únicamente tras comprobar el proyecto y permisos.
- `CUSTOMER_PORTAL_ORIGIN`: origen HTTPS exacto del entorno autorizado. No publicar a producción sin revisar el PR.
- `STRIPE_SANDBOX_SECRET_KEY`: sk_test_… (nunca live). `STRIPE_SANDBOX_WEBHOOK_SECRET`: whsec_… del endpoint de prueba, eventos checkout.session.completed y checkout.session.async_payment_succeeded en /api/customer-portal/stripe-webhook. No pegar secretos en GitHub.
- `commercial_catalog/corporate`: proyección comercial del registro existente de Control; campos appId=corporate, source=nixinx-control, status=active, published=true, name. No crear producto nuevo ni inventar catálogo. Publicar solo tras verificar el registro real y autorización; sincronización pendiente. La API administrativa de Control no es una interfaz pública.
- El importe piloto es 50 centavos CAD (mínimo de Stripe para tarjeta en CAD, documentación https://docs.stripe.com/currencies); no es pricing comercial. No se crea suscripción ni se cobra dinero real.
## Handoff
Webhook con firma válida, relectura de Checkout en sandbox, pago confirmado y conciliación con pedido local crean de forma transaccional un registro único en commercial_provisioning_outbox, status=PENDING_PROVISIONER. El registro contiene requestId, environment=sandbox, datos del perfil, applicationIds, referencia Stripe y estado confirmado. No dispara creación real de recursos. La interfaz consumidora de P03 se define y prueba separadamente; no se llama al endpoint administrativo actual.

No desplegar ni declarar PASS hasta pruebas reales. Mantener el frontend público existente.
