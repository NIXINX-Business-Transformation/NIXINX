# MKT-02 — Zite assessment event API (draft)
Endpoint POST https://nixinx.com/api/marketing/assessment-events. Disabled unless ASSESSMENT_NOTIFICATIONS_ENABLED=true. Server-only variables ASSESSMENT_EVENT_SECRET (64 lowercase hexadecimal characters, interpreted as UTF-8 literal), ASSESSMENT_NOTIFICATION_DAILY_LIMIT (explicit integer 1–100, proposed 20); existing RESEND_API_KEY and Firebase server identity, exact FIREBASE_PROJECT_ID=nixinx-bt. No secret values in repo. No new sending credentials or project. Recipient and sender fixed in server. Zite's existing direct Resend integration must not send this event.

Content-Type application/json; maximum body 2048 bytes. X-Nixinx-Timestamp: ten-digit Unix seconds; X-Nixinx-Signature: lowercase hex HMAC-SHA256 of UTF-8 timestamp + "." + exact raw body bytes. Freshness 300 seconds. Body exactly eventType=assessment.completed, assessmentCode matching NX- plus eight alphanumeric characters (verify actual generator), eventId=assessment-completed:{assessmentCode}, occurredAt canonical Date.toISOString() within 300 seconds. Signature authenticates Zite sender, not independent existence or first completion of a record. Zite must emit only after validated first A persistence and syncAnswers/syncFindings. No B, drafts, previously submitted historical or retry/backfill. Older drafts first completed after activation proposed eligible.

200 DUPLICATE/RATE_LIMITED: no send. 202 ACCEPTED/FAILED/UNKNOWN/AUDIT_PENDING: durable reservation exists, do not retry; ACCEPTED is not delivery. 400 invalid event/body, 401 invalid signature, 413 size, 415 type, 503 disabled/config/reservation unavailable: no deliberate repeat, log sanitized status, preserve evaluation. No exactly-once delivery guarantee. UTC budget and event reservation committed together before sending; durable audit in marketing_assessment_notifications (event docs and separate budget-utc-day-* docs). No expiry on event key. Failed audit leaves PENDING. No PII, access token, payload logs or automatic retries. Operator reconciles manually.

Zite's reported partial persistence failure (status Enviado before sync failure) may prevent future notification. This draft does not fix Zite storage or promise recovery. Owner decision and reconciliation procedure needed before activation; no code changes in Zite authorized by this PR. Zite timeout proposed 3s; NIXINX transport timeout 1.8s, no end-to-end latency guarantee. CI tests simulate serialized transactions, not live Firestore concurrency. Actual integration and security review, project/rules/config checks, activation and live acceptance required. No edits to support, financial, provisioning or evaluation logic.
